## 二、目录职责速查

| 目录 | 一句话 | 放什么 | 不放什么 |
|------|--------|--------|---------|
| `django_edu_manage/` | 项目配置中心 | settings, urls, wsgi, 中间件 | 业务逻辑、Model、API 视图 |
| `django_edu_manage/common/` | 响应/异常/日志基础设施 | response, renderer, exceptions | 业务权限、分页、工具函数 |
| `apps/core/` | 全局可复用的基础设施 | pagination, permissions | 具体业务逻辑 |
| `apps/auth/` | 认证：登录/注册/登出/Token | LoginView, RegisterSerializer | 用户 CRUD、审核（那是 users 的事） |
| `apps/users/` | 用户管理与审核 | User 模型, UserViewSet, 审核 | 认证逻辑（那是 auth 的事） |
| `apps/user_profile/` | 师生档案 | TeacherProfile, StudentProfile | 用户认证逻辑 |
| `apps/classes/` | 班级管理 | 年级枚举, 班级, 班主任关联 | 学生归属（在 StudentProfile 里） |
| `apps/research_group/` | 教研组 | 教研组 CRUD | 教师档案 |
| `apps/dashboard/` | 统计聚合 | 跨表查询、数据汇总 | 原始数据 CRUD |

### 数据流向（以班级列表为例）

```
GET /api/classes/
  → urls.py 匹配 ClassesViewSet
    → permission_classes 鉴权（core.permissions）
      → queryset 查询 (classes.models.Classes)
        → serializer 序列化 (classes.serializers.ClassesSerializer)
          → UnifiedJSONRenderer 包裹 (common.renderer)
            → 分页处理 (core.pagination)
              → JSON 响应
```

### 模型之间的关联

```
User (users)
  ├── 1:1 → TeacherProfile (user_profile) ── M2M ──→ ResearchGroup (research_group)
  │                                              └── M2M ──→ Classes
  ├── 1:1 → StudentProfile (user_profile) ── FK ──→ Classes
  │
  Classes (classes)
    ├── FK → TeacherProfile (headmaster)
    └── 被 StudentProfile.class_id 引用
```

## 四、当前项目的最佳实践

### 4.1 已经在用的好做法

| 实践 | 说明 |
|------|------|
| **Settings 拆分** | `base/development/production` 三个文件，环境隔离清晰 |
| **django-environ** | 环境变量优先级：`.env` → `.env.{env}` → `.env.local` → 系统变量 |
| **统一响应格式** | `ApiResponse` + `UnifiedJSONRenderer`，前端拿到的 JSON 结构永远一致 |
| **JWT + 黑名单** | 无状态认证 + refresh token 轮转 + 登出黑名单 |
| **认证与用户管理分离** | `apps/auth/` 只管认证流程，`apps/users/` 只管用户 CRUD 和审核 |
| **ViewSet + APIView 混用** | 标准 CRUD 用 ModelViewSet，复杂逻辑用 APIView |
| **Serializer 做响应文档** | Dashboard 无 Model 也用 Serializer 声明响应结构 |
| **核心模块分离** | `apps/core/` 存放跨 app 复用的基础设施 |
| **字符串外键引用** | `'user_profile.TeacherProfile'` 避免循环导入 |
| **related_name 显式命名** | 避免 Django 自动生成的反向名冲突 |
| **app_label 显式指定** | `apps/auth` 设置 `label='app_auth'` 避免与 `django.contrib.auth` 标签冲突 |

### 4.2 编码约定

- **Model**：单数命名（`Classes` 而非 `Class`），不与 Python 关键字冲突
- **Serializer**：`{Model}Serializer` 或 `{用途}Serializer`
- **ViewSet**：`{Model}ViewSet`
- **URL**：RESTful 复数形式（`/api/classes/`）
- **权限**：`permission_classes` 列表，`IsAuthenticated` 放前面
- **注释**：解释 WHY 而非 WHAT，代码自解释

## 六、优化详情

### 6.1 移除 `django_app/`

`django_app/` 是 `django-admin startproject` 自动生成的空壳，目录下只有空文件。项目从一开始就没用过它。

**操作**：删除目录 → 从 `INSTALLED_APPS` 移除 → 用 `apps.core` 替代

### 6.2 `IsRole` 归属调整

`IsRole()` 工厂函数放在 `apps/users/permissions.py`，但 `apps/user_profile/views.py` 也在用：

```python
# 之前
from apps.users.permissions import IsRole  # user_profile 依赖 users，"向上依赖"反直觉

# 之后
from apps.core.permissions import IsRole    # 所有模块平等依赖 core
```

### 6.3 认证模块独立 `apps/auth/`

认证功能从 `apps/users` 中拆出，形成独立的 `apps/auth` 模块：

| 迁移内容 | 之前 | 之后 |
|---------|------|------|
| LoginView | apps/users/views.py | apps/auth/views.py |
| LogoutView | apps/users/views.py | apps/auth/views.py |
| TokenRefreshView | apps/users/views.py | apps/auth/views.py |
| RegisterView | apps/users/views.py | apps/auth/views.py |
| RegisterSerializer | apps/users/serializers.py | apps/auth/serializers.py |
| LoginSerializer | apps/users/serializers.py | apps/auth/serializers.py |
| LogoutSerializer | apps/users/serializers.py | apps/auth/serializers.py |
| 认证端点路由 | apps/users/urls.py | apps/auth/urls.py |

**为什么拆？**
- `users` 模块职责过重：既管认证流程又管用户 CRUD 又管审核
- 认证（login/logout/register）和用户管理（list/create/update/delete/approve）是两类不同的关注点
- 独立后 `auth` 不依赖任何业务模块（除了 users.models.User），`users` 也不碰 JWT token 逻辑

### 6.4 合并 `common/` → `apps/core/`（推荐）

当前"基础设施"分散在两处，导入路径不一致：

| 当前导入 | 建议改为 |
|----------|---------|
| `from django_edu_manage.common.response import ok, fail` | `from apps.core.response import ok, fail` |
| `from django_edu_manage.common.exceptions import ...` | `from apps.core.exceptions import ...` |
| `from apps.core.pagination import ...` | `from apps.core.pagination import ...` (不变) |
| `from apps.core.permissions import ...` | `from apps.core.permissions import ...` (不变) |

## 七、新建模块清单

给未来开发者：新增一个业务模块需要创建哪些文件？

```
apps/new_module/
├── __init__.py
├── apps.py          # class NewModuleConfig(AppConfig): name = 'apps.new_module'
├── models.py        # 数据库模型（没有表就跳过）
├── serializers.py   # 序列化器
├── views.py         # ViewSet 或 APIView
├── urls.py          # 路由注册
├── admin.py         # Django Admin 注册（按需）
└── tests.py         # 测试用例
```

然后在以下位置注册：
1. `django_edu_manage/settings/base.py` → `INSTALLED_APPS` 加 `'apps.new_module.apps.NewModuleConfig'`
2. `django_edu_manage/urls.py` → 加 `path('api/new-module/', include('apps.new_module.urls'))`
