## 二、目录职责速查

| 目录 | 一句话 | 放什么 | 不放什么 |
|------|--------|--------|---------|
| `django_edu_manage/` | 项目配置中心 | settings, urls, wsgi, 中间件 | 业务逻辑、Model、API 视图 |
| `django_edu_manage/common/` | 响应/异常/日志基础设施 | response, renderer, exceptions | 业务权限、分页、工具函数 |
| `apps/core/` | 全局基础设施 | BaseViewSet, choices, pagination, permissions, routers | 具体业务逻辑 |
| `apps/auth/` | 认证 | LoginView, RegisterSerializer | 用户 CRUD、审核（那是 users 的事） |
| `apps/users/` | 用户管理与审核 | User 模型, UserViewSet, 审核 | 认证逻辑（那是 auth 的事） |
| `apps/dicts/` | 基础字典（四合一） | SubjectDict, SemesterDict, ResearchGroupDict, ClassDict | 业务逻辑 |
| `apps/students/` | 学生档案（完整 CRUD） | StudentProfileViewSet | 认证、字典数据 |
| `apps/teachers/` | 教师档案（完整 CRUD） | TeacherProfileViewSet | 认证、字典数据 |
| `apps/exam/` | 考试管理 | 考试计划 CRUD、筛选查询 | 成绩存储（那是 score 的事） |
| `apps/score/` | 成绩记录 | 学生/考试/科目绑定与分数存储 | 考试元数据（那是 exam 的事） |
| `apps/dashboard/` | 统计聚合 | 跨表查询、数据汇总 | 原始数据 CRUD |

### 数据流向（以考试列表为例）

```
GET /api/exams?exam_type=MIDTERM&grade=GRADE_7&semester=3
  → urls.py 匹配 ExamPlanViewSet.list()
    → get_permissions() 鉴权（JWT → IsAuthenticated）
      → get_queryset() 按 exam_type/grade/semester 筛选
        → serializer 序列化（ExamPlanSerializer）
          → BaseViewSet.list() 调用 super() 后用 ok() 包裹
            → UnifiedJSONRenderer 检测已包裹 → 直接渲染
              → 分页（StandardResultsSetPagination）
                → JSON 响应
```

### 模型之间的关联

```
User (users)
  ├── 1:1 → TeacherProfile (teachers)
  │           ├── M2M → ResearchGroupDict (dicts)
  │           └── M2M → ClassDict (dicts)
  └── 1:1 → StudentProfile (students)
                └── FK → ClassDict (dicts)

ClassDict (dicts)
  ├── FK → TeacherProfile (headmaster/班主任)
  └── 被 StudentProfile.class_id 引用

ExamPlan (exam)
  ├── FK → SemesterDict (dicts)
  └── grade 使用 GradeChoices 枚举（与 ClassDict.grade 共用）

Score (score)
  ├── FK → StudentProfile (students)
  ├── FK → ExamPlan (exam)
  ├── FK → SubjectDict (dicts)
  └── UniqueConstraint(student, exam, subject)

dashboard 不建表，只做聚合查询
```

## 五、当前项目的最佳实践

### 5.1 已经在用的好做法

| 实践 | 说明 |
|------|------|
| **Settings 拆分** | `base/development/production` 三个文件，环境隔离清晰 |
| **django-environ** | 环境变量优先级：`.env` → `.env.{env}` → `.env.local` → 系统变量 |
| **统一响应格式** | `ApiResponse` + `UnifiedJSONRenderer`，前端 JSON 结构永远一致 |
| **BaseViewSet** | 覆盖 CRUD 六方法，调用 `super()` 后用 `ok()` 包裹，附带中文 message |
| **权限工厂 IsRole** | 支持单角色 `IsRole('ADMIN')` 或多角色 `IsRole(['STUDENT', 'ADMIN'])` |
| **JWT + 黑名单** | 无状态认证 + refresh token 轮转 + 登出黑名单 |
| **认证与用户管理分离** | `apps/auth/` 只管认证，`apps/users/` 只管用户 CRUD |
| **字典模块四合一** | 科目/学期/教研组/班级合入 `apps/dicts/`，减少 app 碎片化 |
| **NoSlashRouter** | 自定义 Router 去掉路由末尾斜杠 |
| **ViewSet + APIView 混用** | 标准 CRUD 用 ModelViewSet，复杂逻辑用 APIView |
| **Serializer 做响应文档** | Dashboard 无 Model 也用 Serializer 声明响应结构 |
| **枚举统一管理** | 所有 TextChoices 归档到 `apps/core/choices.py`，通过 `/api/choices` 暴露 |
| **字符串外键引用** | `'dicts.ResearchGroupDict'` 避免循环导入 |
| **Data Migration** | 种子数据写为 migration，`migrate` 即自动填充 |
| **related_name 显式命名** | 避免 Django 自动生成的反向名冲突 |
| **select_related 预取** | `get_queryset()` 中预取 FK/O2O 关联，避免 N+1 |
| **drf-spectacular** | OpenAPI 3.0 自动生成 + Swagger UI + ReDoc 文档页 |
| **@extend_schema** | 所有 View 均添加 summary/description/parameters，API 文档可读 |

### 5.2 编码约定

- **Model**：单数命名，字典表加 `Dict` 后缀（`ClassDict`, `SubjectDict`）
- **Serializer**：`{Model}Serializer` 或 `{用途}Serializer`
- **ViewSet**：`{Model}ViewSet`，继承自 `apps.core.viewsets.BaseViewSet`
- **URL**：RESTful 复数形式（`/api/classes`、`/api/students`），无末尾斜杠
- **权限**：`permission_classes` 列表，`IsAuthenticated` 放前面
- **表名**：字典表统一 `dict_` 前缀（`dict_subject`、`dict_class` 等）

## 六、新建模块清单

新增一个业务模块需要创建以下文件：

```
apps/new_module/
├── __init__.py
├── apps.py          # class NewModuleConfig(AppConfig): name = 'apps.new_module'
├── models.py        # 数据库模型（没有表就跳过）
├── serializers.py   # 序列化器
├── views.py         # ViewSet（继承 BaseViewSet）或 APIView
├── urls.py          # 路由注册（简单路由用 path，CRUD 用 NoSlashRouter）
├── admin.py         # Django Admin 注册（按需）
└── tests.py         # 测试用例
```

注册步骤：
1. `django_edu_manage/settings/base.py` → `INSTALLED_APPS` 加 `'apps.new_module.apps.NewModuleConfig'`
2. `django_edu_manage/urls.py` → 加 `path('api/', include('apps.new_module.urls'))`

## 七、API 文档体系

项目使用 `drf-spectacular` 自动从代码注释和装饰器生成 OpenAPI 3.0 文档：

| 入口 | 地址 | 说明 |
|------|------|------|
| Swagger UI | `/api/docs/` | 可交互测试的 API 文档 |
| ReDoc | `/api/redoc/` | 只读 API 文档 |
| Schema JSON | `/api/schema/` | OpenAPI 3.0 原始 JSON |

文档来源（按优先级）：
1. `@extend_schema_view` / `@extend_schema` 装饰器中的 `summary` / `description`
2. ViewSet / View 类的 docstring
3. Serializer 字段类型自动推断
